# Refactor-neutrality proof — substitute for the absent Pinebox golden

## Why a substitute was needed

SS-02 nominates its own proof of correctness:

> Do the refactor as a standalone commit with zero behaviour change, verified by
> the Pinebox golden, before any signature code exists. If Pinebox drifts, stop.

`tests/fixtures/Pinebox_Middle_School.pdf` is not in the repo — it is the 3
skips in `tests/test_golden_pinebox.py`. So SS-02's nominated check could not be
run, and 318 passing tests are not the same thing as the byte comparison it asked
for.

## The stronger check that was available

The `Side` refactor left the default `fold_scheme="none"` path **broken** on this
branch (see the pass-1 finding), so there is no working "before" state here to be
neutral against. The meaningful comparison is against **`main`**, where the MVP
worked. That is also a better test than Pinebox would have been: it compares the
real MVP against the real post-refactor code across a settings matrix, rather than
one fixture at one setting.

Method: a `git worktree` of `main`, the same source PDF exported through both
trees via `deckle.cli export`, then comparison of every page's **MediaBox** and
every `cm` (concatenate-matrix) operator extracted from the content streams.

Byte-for-byte PDF comparison is not meaningful — PDFs carry creation timestamps
and document IDs, so the two files differ in hash while being identical as
documents. Placement matrices are the thing the refactor could actually have
broken, and they are exact.

## Results — all IDENTICAL

`tests/fixtures/sample.pdf` (2 pages):

| Settings | Verdict |
|---|---|
| `--gutter 0.75in --binding-edge left` | IDENTICAL |
| `--gutter 0 --binding-edge left` | IDENTICAL |
| `--gutter 18pt --binding-edge right` | IDENTICAL |
| `--gutter 5mm --paper a4` | IDENTICAL |

*Traveller Core Rulebook Update 2022.pdf* (300+ pages, **mixed page sizes** — the
cover is narrower than the body, which is what exercises `document_scale`):

| Settings | Verdict |
|---|---|
| `--gutter 0.75in --binding-edge left` | IDENTICAL |
| `--gutter 0.5in --binding-edge right` | IDENTICAL |

Identical means: same page count, same MediaBox per page, same ordered list of
`cm` matrices per page. Example from `sample.pdf`:

```
page 0: 0.91176 0 0 0.91176 54 34.94118
page 1: 0.91176 0 0 0.91176  0 34.94118
```

The mixed-size book is the load-bearing case. Per-page scaling would have made the
narrower cover's text render larger than the body's — the exact defect
`document_scale` exists to prevent — and that would have shown as a differing
`scale_x`/`scale_y` on page 0. It does not.

## The zero-diff seam, verified independently

The design's central claim is that `deckle/core/printing.py` and
`deckle/core/profiles.py` do not change at all. Verified by diff, not by grep:

```
git diff --stat main -- deckle/core/printing.py deckle/core/profiles.py
(empty)
```

The spec's own grep guard also passes:
`! grep -n "\.front|\.back|Side|Signature|Mark|marks" deckle/core/printing.py deckle/core/profiles.py` → exit 0.

## What this does not prove

- It compares **placements**, not rendered pixels. A change in how content
  streams are composed that preserved every matrix would pass this and still
  alter output. `pikepdf`'s `as_form_xobject` path makes that unlikely, but it is
  not excluded.
- It covers `fold_scheme="none"` only. The folio path is new, so it has no
  `main` counterpart to be neutral against — its correctness rests on
  `tests/test_layout_saddle.py`, `tests/test_integration_signatures.py`, and
  ultimately on SS-13's physical folded dummy, which remains `manual_pending`.
- Obtaining the real Pinebox fixture would still be worth doing. This proof is
  broader but it is generated by the same codebase whose exporter it exercises;
  an external golden is independent of that.
