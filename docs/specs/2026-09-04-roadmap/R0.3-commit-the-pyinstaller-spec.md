## 1. Context

`run.bat package` and `tests/test_packaging_audit.py` both read
`packaging/deckle.spec`. The file is not in the repository and the directory
does not exist:

```
$ ls packaging/
"packaging/": No such file or directory (os error 2)
$ git check-ignore -v packaging/deckle.spec
.gitignore:21:*.spec	packaging/deckle.spec
```

`.gitignore:21` is `*.spec` under a `# PyInstaller` heading. That pattern is
meant for the spec files PyInstaller *generates* from a command line; it also
swallows the one that is hand-maintained source.

The consequences, in order of how much they cost:

1. **Nobody can produce a release build.** Not "nobody can build on Linux" —
   nobody at all, including a second Windows machine, including the author
   after a reinstall. The one artifact that has ever shipped exists because
   one working tree had an untracked file in it.
2. **The release licence gate is unrunnable.** `tests/test_packaging_audit.py`
   is what stands between an MIT release and an AGPL library that PyInstaller
   reached into the build environment for — the failure that actually
   happened, recorded in `docs/decisions.md`, *2026-08-04 — The first
   packaged build bundled an AGPL library* (1.6 GB, containing `pymupdf`).
   Its tests skip when `dist/deckle` is absent, so the whole file passes
   vacuously; only the one test that reads the spec file *fails*, and it
   fails with a `FileNotFoundError` that says nothing about any of this.
3. **The suite is red on every clone.** Verified on the current tree:


## 3. Change

There are two implementers. Take whichever branch applies; the acceptance
table in §5 is the same for both.

### Branch A — you are on the Windows machine that has the file

This is the preferred branch, because that file has produced a bundle that
passed the audit and an authored one has not.

1. `git add .gitignore` after step A2, then `git add -f packaging/deckle.spec`.
2. Edit `.gitignore`. Replace line 21 (`*.spec`) with the pattern plus a
   negation, exactly:

   ```
   *.spec
   !packaging/deckle.spec
   ```

   Keep the surrounding `# PyInstaller` block otherwise untouched. The
   negation must come **after** the pattern; git takes the last matching
   rule.
3. Read the file before committing it and confirm it contains no absolute
   path from your machine (`C:\Users\...`), no `.buildenv` path, and no
   `pathex` entry outside the repository. If it does, replace those with
   paths relative to `SPECPATH`. A spec that only works in one checkout is
   the bug this spec is fixing, one layer down.
4. Confirm it satisfies §2's two greps (`exception`, `GPL`). If the licence
   comment is absent, add the block from Branch B step 4 verbatim at the top.
5. Skip to step 6 (common).

### Branch B — you do not have the file; author it

Write `packaging/deckle.spec` with exactly the content below. It is a
PyInstaller spec, which is a Python script executed with `SPECPATH`,
`DISTPATH` and `workpath` already bound; do not add imports beyond the two
shown.

```python
# -*- mode: python ; coding: utf-8 -*-
#
# Deckle's PyInstaller spec. Hand-maintained source, not generated output --
# `.gitignore`'s `*.spec` is for the ones PyInstaller writes for you, and
# this file is negated out of it. It was untracked for the first month of
# the project's life, which meant exactly one machine on earth could produce
# a release build or run the licence gate that guards one.
#
# LICENCE, and why this bundling is lawful. PyInstaller is licensed
# GPLv2-or-later WITH an explicit exception permitting the distribution of
# bundled programs under any licence the author chooses. Deckle is MIT.
# Without that exception, freezing an MIT app with a GPL tool and shipping
# the result would be a licence violation, so the reasoning is written here
# rather than rediscovered by whoever next wonders. PyInstaller is
# build-time only -- it is in the `package` extra, never in
# `[project].dependencies`, and never enters the runtime closure that
# `tests/test_license_audit.py` walks.
#
# NOT a place to fix a fat bundle. The first build produced 1.6 GB
# containing torch, paddle, cv2 and pymupdf -- pymupdf being AGPL-3.0, which
# would have made the artifact undistributable. The fix is to build from
# `.buildenv`, a clean virtualenv holding only the declared dependencies;
# see `run.bat package`. Excluding offenders by name here is whack-a-mole
# against an environment you do not control, and the next machine has a
# different set. The `excludes` below are for one thing only: keeping Qt out
# of the headless CLI binary.

from PyInstaller.utils.hooks import collect_submodules, copy_metadata

# Third-party submodules PyInstaller's static analysis does not reach.
# Deckle's own modules are NOT listed: the analysis traces those from the
# entry point, which is why adding `core/schema.py` needed no change here.
_HIDDEN = (
    collect_submodules("pikepdf")
    + collect_submodules("pypdfium2")
    + collect_submodules("img2pdf")
)

# `deckle --version` reads installed-distribution metadata rather than
# importing the packages, so that the CLI never has to import PySide6. A
# frozen build ships no .dist-info by default, and the lookup then returns
# the string "not installed" for every dependency -- silently wrong output
# from the one command whose entire job is to answer "what am I running"
# for a bug report.
_METADATA = (
    copy_metadata("pikepdf")
    + copy_metadata("pypdfium2")
    + copy_metadata("img2pdf")
    + copy_metadata("PySide6")
    + copy_metadata("natsort")
    + copy_metadata("Pillow")
)

gui_analysis = Analysis(
    ["../deckle/__main__.py"],
    pathex=[".."],
    binaries=[],
    datas=_METADATA,
    hiddenimports=list(_HIDDEN),
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=[],
    noarchive=False,
)

# The CLI is built Qt-free on purpose: `deckle.core` imports no Qt binding
# (`tests/test_core_purity.py` enforces it) and `deckle.cli` never imports
# `deckle.app`, so the headless binary runs on a server with no display
# libraries installed at all. The excludes are belt and braces -- if one of
# them ever starts mattering, something has imported Qt from the core and
# `test_core_purity` should have caught it first.
cli_analysis = Analysis(
    ["../deckle/cli.py"],
    pathex=[".."],
    binaries=[],
    datas=_METADATA,
    hiddenimports=list(_HIDDEN),
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=["PySide6", "shiboken6", "PyQt5", "PyQt6", "tkinter"],
    noarchive=False,
)

# Deliberately no MERGE(). It would de-duplicate the two analyses' shared
# binaries, and it also rewrites where each executable expects to find them
# -- which is a thing to get wrong on a machine that cannot run the result.
# COLLECT already writes each destination name once, and the bundle is
# nowhere near the 700 MB ceiling (the known-good Windows build was 160 MB).

gui_pyz = PYZ(gui_analysis.pure)
cli_pyz = PYZ(cli_analysis.pure)

gui_exe = EXE(
    gui_pyz,
    gui_analysis.scripts,
    [],
    exclude_binaries=True,
    name="deckle",
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=False,
    # Windowed: the GUI must not open a console behind itself. The CLI
    # below is the opposite, and getting these two the wrong way round
    # produces a GUI with a stray black window and a CLI that prints
    # nowhere.
    console=False,
)

cli_exe = EXE(
    cli_pyz,
    cli_analysis.scripts,
    [],
    exclude_binaries=True,
    name="deckle-cli",
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=False,
    console=True,
)

# One folder, not one file. `tests/test_packaging_audit.py` walks
# `dist/deckle/` and requires both executables as files directly inside it,
# and a one-file build would leave nothing there to audit -- the whole
# bundle would be sealed inside two self-extracting binaries and the licence
# gate would have nothing to look at.
COLLECT(
    gui_exe,
    gui_analysis.binaries,
    gui_analysis.datas,
    cli_exe,
    cli_analysis.binaries,
    cli_analysis.datas,
    strip=False,
    upx=False,
    upx_exclude=[],
    name="deckle",
)
```

Then:

5. `git add .gitignore packaging/deckle.spec`.

## 8. Traps

- **The two greps in the existing test are case-asymmetric.** `"exception"`
  is checked against `spec.lower()`; `"GPL"` is checked against the raw
  text. A file that says "gpl" in lower case fails.
- **The negation must come after the pattern.** `!packaging/deckle.spec`
  above `*.spec` does nothing.
- **`git add packaging/deckle.spec` before the `.gitignore` edit is silent.**
  It prints nothing and stages nothing. Check `git status --short packaging`.
- **`git` cannot un-ignore a file inside an ignored directory.** It is
  `packaging/` here and `packaging/` is not itself ignored, so this is fine —
  but if you create the file at a different path under an ignored directory,
  the negation will not work and you will need `!dir/` first.
- **One-folder, not one-file.** `test_both_executables_are_produced` reads
  `dist/deckle/` with `iterdir()` and wants both binaries as files there.
- **`console=False` on the GUI, `console=True` on the CLI.** Swapped, the GUI
  grows a stray console window and the CLI prints into the void — the second
  failure is invisible until somebody pipes it.
- **PyInstaller cannot cross-compile.** Authoring this on Linux does not
  produce a Windows build and does not test one; the `@requires_bundle` tests
  will keep skipping. Say so in the commit message rather than implying a
  build happened.
- **`.buildenv/` is gitignored** (`.gitignore`, last block). Do not commit it,
  and do not build from your own interpreter — that is the 1.6 GB / AGPL
  failure, and it is the reason the audit exists.
- `run.bat` has structural tests of its own
  (`test_run_bat_package_target_points_at_this_file`,
  `test_run_bat_contains_no_stray_control_characters`). Do not edit `run.bat`
  in this spec; if you find yourself wanting to, read those tests first.
