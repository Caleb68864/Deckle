# R0.1 — Commit `tests/fixtures/sample.pdf` so a fresh clone can run the suite

**Roadmap item:** `docs/ROADMAP.md` R0.1
**Depends on:** —
**Blocks:** R0.6 (CI has nothing to run until this lands), and every other
spec's acceptance table, which assumes a green suite.
**Size:** S
**Decision needed first:** none. The one design choice — commit the file
versus generate it — is made in §3 and does not need the owner.

---

## 1. Context

`tests/fixtures/sample.pdf` is the two-page Letter PDF that 22 test modules
open. It is not in the repository: `.gitignore:28` matches
`tests/fixtures/*.pdf`, so it has never been committed. It exists only on
machines where somebody happened to make one.

The consequence for a person cloning Deckle is that the test suite is
mostly red before they have written a line, and nothing in the failure text
says why. This matters beyond developer comfort: the suite is the only
thing standing between a layout change and a ruined ream, and a suite that
is red on arrival stops being consulted.

Reproduced on a fresh clone of `08e7f49` (Linux, `QT_QPA_PLATFORM=offscreen`,
a venv with `.[dev]` **and** `numpy`, so that R0.2 is not confounding this):

```bash
git clone . /tmp/deckle-clone
cd /tmp/deckle-clone
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q --no-header -p no:cacheprovider
```

Output, last line:

79 failed, 1405 passed, 22 skipped, 3 warnings, 25 errors in 49.68s

**The roadmap's wording is imprecise here and the difference matters to
whoever reads the output.** ROADMAP R0.1 says "79 failures + 25 collection
errors". Collection succeeds: `pytest --collect-only` on the same clone
reports `1531 tests collected in 3.79s` with no errors. The 25 `ERROR`s are
**fixture-setup errors** raised inside `tests/test_gui_workflow.py` and
`tests/test_project_cli.py` fixtures, after collection, when the fixture
tries to load the missing PDF. The failure *count* — 79 and 25 — is exactly
right; only the phase is wrong. (The genuine collection abort belongs to
R0.2.)

`tests/fixtures/README.md` compounds it by describing the file as
"checked-in" and "No setup required", which is D9.

This is why collection survives: the constant is a string, and nothing opens
it until a test or a fixture runs.

There is **no `tests/conftest.py`** in the tree (`ls tests/conftest.py` →
"No such file or directory"). Any generation-based fix would have to create
one.

The file that is present on this working machine, for reference — it is what
the committed one must match in shape:

```
2 pages, both MediaBox [0.0, 0.0, 612.0, 792.0], 1480 bytes
```

That is `deckle dummy -o tests/fixtures/sample.pdf --pages 2` output:
`deckle/core/dummy.py:29` defines `LETTER_PT = (612.0, 792.0)` and
`make_numbered_pdf` defaults `page_size` to it (`dummy.py:106`). The pages
carry a large Helvetica numeral, an underline and a `HEAD` label, so the
fixture has real ink — several tests measure it, and a blank two-page PDF
would not do.

## 3. Change

**Chosen: un-ignore the file and commit it. Rejected: generate it in a
`tests/conftest.py` session fixture.**

Committing wins on three counts. (1) The bytes are then stable: `deckle
dummy` is *not* byte-reproducible — two runs a second apart produced sha256
`90ad3e4d…` and `66dd5cac…`, because pikepdf writes a fresh `/ID` — so a
generated fixture silently changes under every test that measures pixels.
(2) It removes a chicken-and-egg: with generation, a defect in
`deckle.core.dummy` turns ~100 unrelated tests into errors instead of
failing `tests/test_dummy.py`. (3) It makes `tests/fixtures/README.md` true
rather than needing an edit (see D9 in `D-docs-pass.md`, which keeps that
row but retires it as fixed by this spec).

The file is 1.5 KB. That is not a reason to argue about binaries in git.

### Steps

1. **`.gitignore`** — replace the single fixture rule (line 28) with the
   rule plus a negation, keeping the existing `# Test fixtures` comment
   line above it. Exact replacement text for lines 27-28:

   ```
   # Test fixtures. sample.pdf is the one exception: ~100 tests open it and a
   # fresh clone must be green, so it is tracked. The golden Pinebox fixture
   # is 30 MB and stays out -- its test skips when it is absent.
   tests/fixtures/*.pdf
   !tests/fixtures/sample.pdf
   ```

   Order matters: the negation must come **after** the pattern it negates.

2. **Generate the fixture** (skip if you already have one that is 2 pages
   of Letter — a Windows checkout may). From the repo root:

   ```bash
   .venv/bin/python -m deckle.cli dummy -o tests/fixtures/sample.pdf --pages 2
   ```

   Do **not** use `python -m deckle`; that launches the GUI and blocks.

3. **Normalise the mode.** The generator writes `0600` via
   `paths.atomic_output`'s `mkstemp`. Git stores only the executable bit, so
   this is cosmetic in the repository, but it makes a subsequent
   `git checkout` on the author's machine confusing. Run:

   ```bash
   chmod 644 tests/fixtures/sample.pdf
   ```

4. **Stage it.** With the negation in place a plain `git add` works; the
   `-f` is belt and braces and harmless:

   ```bash
   git add .gitignore tests/fixtures/sample.pdf
   git status --short tests/fixtures
   ```

   `git status --short` must show `A  tests/fixtures/sample.pdf`.

5. **Add the regression test** in §4 (`tests/test_fixture_is_tracked.py`).

6. **Update `docs/api/`**: nothing. No new module.

No Python source changes. Note that the pre-commit hook
(`scripts/hooks/pre-commit`) only demands a `docs/decisions.md` entry when
a staged file matches `\.(ts|js|py|rb|go|rs|cs|sql|sh)$`; step 5 adds a
`.py`, so it will fire. §7 has the entry.

## 4. Tests

New file: **`tests/test_fixture_is_tracked.py`**.

It asserts the property that actually broke — the fixture is *in the
repository*, not merely on this disk. A test that only checks
`os.path.exists` passes on the machine that has one and is exactly the test
that was missing.

```python
"""The sample fixture is tracked, not merely present.

A fresh clone got 79 failures and 25 fixture-setup errors because
``tests/fixtures/sample.pdf`` was matched by ``tests/fixtures/*.pdf`` in
``.gitignore`` and had never been committed, while
``tests/fixtures/README.md`` described it as checked in. Every existing
test that uses the fixture passes on a machine that happens to have one,
so none of them could catch this; the thing to assert is what ``git``
knows, not what the filesystem knows.
"""
```

| Test function | Setup | Assertion in words | Failure on the unfixed tree |
|---|---|---|---|
| `test_the_sample_fixture_is_tracked_by_git` | `subprocess.run(["git", "ls-files", "--error-unmatch", "tests/fixtures/sample.pdf"], cwd=REPO_ROOT)` | exit code is 0 — git knows the path | `AssertionError` naming the returncode `1` and git's `did not match any file(s) known to git` on stderr |
| `test_the_sample_fixture_is_not_ignored` | `subprocess.run(["git", "check-ignore", "-v", "tests/fixtures/sample.pdf"], cwd=REPO_ROOT)` | exit code is **1** (git's "not ignored") | today it exits 0 and prints `.gitignore:28:tests/fixtures/*.pdf`, so the assertion fails with that line in the message |
| `test_the_sample_fixture_is_two_letter_pages` | `pikepdf.open(FIXTURE)` | exactly 2 pages, every MediaBox `[0, 0, 612, 792]` within `1e-6` | passes on a machine that has the file; fails with `FileNotFoundError` on a fresh clone. This is the one that pins the *shape*, so a future regeneration at A4 or 4 pages is caught |

Skip guard: both git tests must `pytest.skip("not a git checkout")` when
`(REPO_ROOT / ".git").exists()` is false, so a source tarball does not fail
them. Do **not** skip when `git` is merely missing from `PATH`; a CI image
without git is a CI bug worth seeing.

No existing test needs changing.

## 6. Out of scope

  the 30 MB golden fixture.

## 8. Traps

- **`git add tests/fixtures/sample.pdf` before editing `.gitignore` appears
  to work** — git prints nothing and does nothing. Check
  `git status --short tests/fixtures` for the `A ` line; do not trust
  silence. If you are on a checkout where the file was already force-added
  at some point, `git ls-files` will show it and step 4 is a no-op.
- **The negation must follow the pattern.** `!tests/fixtures/sample.pdf`
  placed above `tests/fixtures/*.pdf` has no effect; git takes the last
  matching rule.
- **Do not run `python -m deckle`** to make the fixture. That launches the
  GUI and blocks forever. It is `python -m deckle.cli dummy`.
- **The 25 errors are setup errors, not collection errors** (see §1). If you
  are diagnosing and see `1531 tests collected` with no error, that is
  correct and this bug is still present.
- The suite writes nothing to `tests/fixtures/`. If a run leaves a modified
  `sample.pdf` in `git status`, something has started mutating the source —
  `tests/test_repeated_source_page.py::test_the_source_file_is_left_as_it_was_found`
  guards exactly that property for a temp copy, and a dirty fixture means it
  should be extended, not that the fixture should be re-ignored.
- Windows checkouts: line-ending normalisation must not touch a `.pdf`.
  Already handled — `.gitattributes` carries `*.pdf       binary` in its
  "Common binaries — never normalize, never diff as text" block. Nothing to
  add; do check that the file is still there before committing, because a
  `text=auto` PDF on a Windows checkout is corrupt on arrival and the
  symptom is a `pikepdf` parse error nobody will connect to git.
