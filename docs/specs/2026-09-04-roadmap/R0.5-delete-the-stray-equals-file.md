## 1. Context

An empty file whose entire name is `=` is tracked at the repository root.

It has no effect on the program. It has an effect on the people reading the
repository: it is the first thing `ls` shows, it appears in every `git
status` glance, and nobody can tell by looking whether it matters. A stray
artefact that nobody dares delete is a small tax charged on every future
reader, and it is charged forever.

It also documents something worth knowing: a shell redirect went into the
working tree and got committed, and no check noticed.

Verified:

```
$ git ls-files --error-unmatch '='
=
$ ls -la ./=
.rw-r--r-- 0 caleb  4 Sep 10:22 ./=
```

Zero bytes.

Provenance — the roadmap's guess is right, and here is the evidence:

```
$ git log --oneline --all -- '='
b549d95 test(folio): pin the gutter to the fold, and fix a vacuous assertion
$ git show --stat b549d95
...
 =                           |  0
 docs/decisions.md           |  7 +++++
 tests/test_layout_saddle.py | 74 +++++++++++++++++++++++++++++++++++++++++++--
```

`b549d95` (Wed Aug 5 2026) is the commit whose message says *"asserted only
`'>= 0.0'`"*. A `>=` typed at a shell prompt is `>` followed by `=`: the
shell creates a file called `=` and truncates it to nothing. The file has
been in every clone since.

## 2. Current code

There is none. The file is empty and nothing references it:

$ grep -rn "\"=\"\|'='" deckle/ tests/ run.bat pyproject.toml
(no output relevant to a file: only Python operators)
```

Every tracked path whose components are not `[A-Za-z0-9._-]+`:

= -> =
```

Exactly one. The repository is otherwise clean, which is what makes a rule
about it cheap to enforce.

Tracked files at the repository root, for context on what a root-level guard
would be judging (`git ls-files | awk -F/ 'NF==1'`):

```
.gitattributes  .gitignore  =  CHANGELOG.md  LICENSE  README.md
forge-project.json  pyproject.toml  run.bat
```

227 tracked files in total. Two are empty: `=` and `tests/__init__.py` — the
second is a legitimate package marker, which is why the guard in §4 keys off
the *name* and not the size.

No test mentions this file. There is no existing repository-hygiene test
module.

## 3. Change

1. **Delete it.** From the repository root:

   ```bash
   git rm '='
   ```

   Quote it. Unquoted, `git rm =` is fine in `bash` and `zsh` today, but the
   quoting is the point of the exercise.

2. **Add the guard** described in §4, as a new file
   `tests/test_repo_hygiene.py`.

3. Nothing else. Do not add `=` to `.gitignore` — the file should not exist,
   and an ignore rule would hide the next one instead of reporting it.

**Chosen: a name-shape rule over all tracked paths. Rejected: a hard-coded
"there is no file called `=`" assertion.** The second passes the moment this
commit lands and never fires again; the failure mode it is guarding against
is "a shell redirect landed in the tree", and the next one will be called
`2` or `1` or `>`, not `=`.

The character class is `[A-Za-z0-9._-]`. Deliberately no space and no
non-ASCII: a repository that is cloned onto Windows, Linux and macOS, built
by PyInstaller and walked by `os.walk` in three different tests has no use
for a filename that needs quoting, and `tests/test_packaging_audit.py`
already records what an invisible character in a path cost this project once
(`test_run_bat_contains_no_stray_control_characters`, and the tab that made
`pytest tests<TAB>est_packaging_audit.py`).

## 8. Traps

- **Quote the argument.** `git rm '='`. An unquoted `=` is fine in
  `bash`/`zsh` as a plain word, but `rm =*` or a `find` predicate written
  without quotes will surprise you, and this is a bad file to be casual with.
- **`git rm` and not `rm`.** The file is tracked; deleting it from disk alone
  leaves it staged-as-deleted-nowhere and it comes back on the next checkout.
- **Do not add it to `.gitignore`.** See §3 step 3.
- **The guard is `git ls-files`, not `os.walk`.** Walking the filesystem would
  pick up `.venv/`, `dist/`, `build/`, `graphify-out/` and every ignored
  scratch directory, and it would fail on somebody's machine for reasons that
  are not the repository's business.
- The §5 hygiene check is verified against the current tree: it prints
  `['=']` and exits 1 today. If you rewrite it, re-verify it still fails
  *before* the deletion, or the acceptance row is worthless.
- `python -m deckle` launches the GUI. Nothing in this spec needs to run the
  program at all.
