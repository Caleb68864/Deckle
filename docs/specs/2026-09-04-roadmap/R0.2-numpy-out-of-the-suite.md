# R0.2 — Take `numpy` out of the test suite so collection cannot abort

**Roadmap item:** `docs/ROADMAP.md` R0.2
**Depends on:** —
**Blocks:** R0.6 (CI installs `.[dev]` and nothing else)
**Size:** S
**Decision needed first:** none. The roadmap offers two options ("Add it to
`dev` extras or rewrite the test without it"); §3 picks one and says why.

---

## 1. Context

`tests/test_repeated_source_page.py` imports `numpy` at module level.
`numpy` is not in `[project.optional-dependencies].dev`, is not a runtime
dependency, and is not installed by `run.bat deps`. It is present on the
author's machine and nowhere else.

The failure is not "one test errors". **Pytest refuses to run any test at
all when a module fails to import during collection.** So on a fresh
`.[dev]` install the entire suite — 1531 tests — is replaced by a single
`ImportError` for a file that has nothing to do with whatever the person
was working on.

Reproduced by shadowing `numpy` with a module that raises, on a fresh clone:

```bash
mkdir -p /tmp/nonumpy/numpy
echo 'raise ImportError("No module named '"'"'numpy'"'"'")' > /tmp/nonumpy/numpy/__init__.py
QT_QPA_PLATFORM=offscreen PYTHONPATH=/tmp/nonumpy \
  .venv/bin/python -m pytest -q --no-header -p no:cacheprovider \
  tests/test_layout.py tests/test_repeated_source_page.py tests/test_paper.py
```

Output:

```
tests/test_repeated_source_page.py:35: in <module>
    import numpy as np
...
E   ImportError: No module named 'numpy'
=========================== short test summary info ============================
ERROR tests/test_repeated_source_page.py
!!!!!!!!!!!!!!!!!!!! Interrupted: 1 error during collection !!!!!!!!!!!!!!!!!!!!
1 error in 1.23s
```

`tests/test_layout.py` and `tests/test_paper.py` were named on the command
line and neither ran. Note the exit status: pytest returns **2**
(`EXIT_INTERRUPTED`), not 1, which is a different thing for a CI step to
report.

Contrast `tests/test_export.py:330`, which needs `psutil` — also
undeclared — and reaches for it with `psutil = pytest.importorskip("psutil")`
*inside* the test body. That one has never blocked anybody. The defect here
is the top-level import, not the dependency.

def _ink_widths(path: str) -> list[int]:
    """The ink width on each exported sheet, in pixels."""
    widths: list[int] = []
    doc = pypdfium2.PdfDocument(path)
    try:
        for index in range(len(doc)):
            page = doc[index]

            finally:

            widths.append(int(columns.max() - columns.min()) if columns.size else 0)
    finally:

    return widths

## 3. Change

**Chosen: rewrite `_ink_widths` on Pillow, which is already a runtime
dependency. Rejected: add `numpy` to `[dev]`.**

One line in `pyproject.toml` would also work and is a smaller diff. It is
the worse trade: it makes every contributor and every CI job download a
~20 MB wheel to compute one bounding box that the library already in the
closure computes, and it puts a third entry in a `dev` list whose two
existing entries each carry a written justification. The rewrite deletes
the dependency question instead of answering it.

**The replacement is numerically identical, not merely equivalent.**
Verified by running both implementations over the same four-page export:

```
numpy: [71, 70, 71, 70]
pil  : [71, 70, 71, 70]
equal: True
```

Why they agree exactly: `np.where(array < 200)` yields the column indices
of dark pixels, and the old code returns `max - min`. Thresholding to a
mask and taking `Image.getbbox()` gives `(left, upper, right, lower)` where
`left == min` and `right == max + 1`. So `right - left - 1` is the same
integer, and `getbbox()` returning `None` on an all-blank page is the same
case as `columns.size == 0`.

### Steps

1. **`tests/test_repeated_source_page.py`**, imports (lines 33-37). Delete
   `import numpy as np` and add Pillow. The block becomes:

   ```python
   import os

   import pypdfium2
   import pytest
   from PIL import Image
   ```

   `Image` is imported for the type only; if the implementer prefers not to
   carry an unused name, drop it — the body below does not need it. Either
   is fine; do not add anything else.

2. **`tests/test_repeated_source_page.py`**, replace `_ink_widths`
   (lines 55-73) with exactly:

   ```python
   def _ink_widths(path: str) -> list[int]:
       """The ink width on each exported sheet, in pixels.

       Pillow rather than numpy, and not for taste: numpy was the only
       thing in the suite that a fresh ``.[dev]`` install did not have,
       and a module-level import of it turned every one of the 1531
       tests into a single collection error. Pillow is already a runtime
       dependency and ``page.render(...).to_pil()`` already returns one
       of its images.

       ``getbbox`` on the thresholded mask gives the same integer the
       ``np.where`` version did: its ``right`` is one past the last dark
       column, so ``right - left - 1`` is ``columns.max() -
       columns.min()``. Verified equal on the four-sheet export this
       file measures.
       """
       widths: list[int] = []
       doc = pypdfium2.PdfDocument(path)
       try:
           for index in range(len(doc)):
               page = doc[index]
               try:
                   ink = (
                       page.render(scale=0.5)
                       .to_pil()
                       .convert("L")
                       .point(lambda value: 255 if value < 200 else 0)
                   )
               finally:
                   page.close()
               box = ink.getbbox()
               widths.append(box[2] - box[0] - 1 if box else 0)
       finally:
           doc.close()
       return widths
   ```

   The `try/finally` around the render is kept as it was: pdfium page
   handles are closed eagerly here on purpose.

3. **`docs/specs/2026-09-04-roadmap/00-environment.md`** — delete line 10,
   `.venv/bin/pip install numpy            # until R0.2 lands`. This is the
   one file outside the code that names the workaround.

4. Add the guard test in §4.

5. Do **not** touch `pyproject.toml`. Do not add `numpy` anywhere.

## 4. Tests

### The existing six are the real test

They already assert the crop behaviour; the change is to how they measure
it. Before editing, record the current output so the rewrite is checked
against a number and not a hope:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest \
  tests/test_repeated_source_page.py -q --no-header -p no:cacheprovider
```

On the current tree (with numpy installed) this is `6 passed`. It must
still be `6 passed` after, **and** with numpy shadowed out:

```bash
QT_QPA_PLATFORM=offscreen PYTHONPATH=/tmp/nonumpy .venv/bin/python -m pytest \
  tests/test_repeated_source_page.py -q --no-header -p no:cacheprovider
```

### The new guard

New file: **`tests/test_suite_imports_only_declared_dependencies.py`**.

The bug is not "numpy"; it is "a test module imports, at module level, a
distribution the project does not declare, and pytest then runs nothing".
That property is what to pin, because the next one will be `scipy` or
`opencv` and the symptom will be identically confusing.

| Test function | Setup | Assertion in words | Failure on the unfixed tree |
|---|---|---|---|
| `test_no_test_module_imports_an_undeclared_third_party_package_at_module_level` | Parse every `tests/**/*.py` with `ast`. Walk **only the direct children of `tree.body`**, collecting the top-level package name from each `ast.Import` alias and from each `ast.ImportFrom` whose `level == 0`. Allowed = `sys.stdlib_module_names` ∪ `{"pytest", "hypothesis"}` ∪ the import names of `pyproject.toml`'s `[project].dependencies` (`pikepdf`, `pypdfium2`, `img2pdf`, `natsort`, `PIL`, `PySide6`) ∪ `{"deckle", "packaging"}` | the set of offending `(file, name)` pairs is empty | `AssertionError: undeclared module-level imports in the test suite: [('tests/test_repeated_source_page.py', 'numpy')] -- import it inside the test with pytest.importorskip, or declare it` |

Notes for whoever writes it:

- **Direct children of `tree.body`, not `ast.walk`.** Verified against the
  current tree: that scan returns exactly
  `[('tests/test_repeated_source_page.py', 'numpy')]` and nothing else.
  `ast.walk` would additionally flag `tomli` at
  `tests/test_license_audit.py:25`, which sits inside a
  `if sys.version_info >= (3, 11): ... else:` block, is unreachable on every
  interpreter this project supports (`requires-python = ">=3.11"`), and is
  not a defect. Widening the scan is a separate argument to have; do not
  have it inside this spec.
- `Pillow` installs as the import name `PIL`; hard-code that mapping rather
  than trying to resolve distributions to modules. The list is six entries
  and it is in `pyproject.toml` two feet away.
- `packaging` is allowed because `tests/test_license_audit.py:27` imports
  `packaging.requirements` at module level and it arrives with setuptools;
  that is a pre-existing, deliberate case and this spec does not relitigate
  it. Say so in the allow-list comment.
- Deliberately **module-level only**. `tests/test_export.py:330` reaching
  for `psutil` inside the body via `pytest.importorskip` is the pattern this
  test is steering people toward, so it must not flag it.

To confirm the guard fails for the right reason before making the fix, run
it first: on the unfixed tree it must name `numpy` and
`tests/test_repeated_source_page.py` and nothing else.

## 6. Out of scope

- **R0.1.** On a clone with neither fix, this collection abort happens
  *first* and hides R0.1's 79 failures entirely. Do not conclude R0.1 is
  fixed because the numbers changed.
- **`psutil`.** `tests/test_export.py:330` uses `pytest.importorskip` and is
  correct as it stands. Do not "fix" it by declaring psutil, and do not
  delete the skip.
- The six assertions in `tests/test_repeated_source_page.py` are not to be
  retuned. Their tolerances (`<= 2`, `>= widths[0] - 2`) were chosen against
  measured pixel counts; the replacement produces the identical integers, so
  there is nothing to adjust. If a tolerance now needs changing, the
  rewrite is wrong.
- `run.bat deps` installs `pytest psutil` rather than `.[dev]` and so misses
  `hypothesis` too. That is a real inconsistency and it belongs with R0.6's
  companion work on the Windows launcher, not here.

## 8. Traps

- **`pytest -k` and naming files does not route around a collection error.**
  If you are testing the fix by running one file, you are not reproducing the
  bug. Use `--collect-only` over the whole suite.
- **Exit code 2, not 1.** A CI step that only checks "non-zero" is fine, but
  a script branching on `== 1` will misreport this.
- `Image.point(lambda ...)` on a mode-`"L"` image builds a 256-entry lookup
  table, so the lambda runs 256 times, not once per pixel. It is not the
  slow path it looks like. Do not "optimise" it into a per-pixel loop.
- `getbbox()` returns `None`, not an empty tuple, for an all-zero image.
  `box[2] - box[0] - 1 if box else 0` is written in that order deliberately.
- The suite writes no PDFs into `tests/fixtures/`; this file makes its own
  sources in `tmp_path` via `deckle.core.dummy.make_numbered_pdf`, so it is
  one of the few modules that does **not** depend on R0.1.
- Do not run `python -m deckle` while debugging this; it launches the GUI and
  blocks. `python -m deckle.cli` is the headless entry point.
